## Reading states and evidence

- **not implemented**: no complete native action. Reusable Tauri/core code may
  exist; that alone is not an implemented native workflow.
- **implemented-unverified**: native source/model/service exists, but the stated
  release-window scenario lacks sufficient acceptance evidence. Focused tests do
  not establish UI, lifecycle, keyboard/AX or IME parity.
- **passed**: only the specific scenario and historical binary identified by its
  evidence entry passed. This never silently transfers to later source changes.
- **blocked**: an identified prerequisite prevents the action's acceptance.
  The blocker is stated in the row. An absent action is not called blocked merely
  because implementing it remains work.
- **excluded** is used only in the explicit non-PostgreSQL/deferred section.

`None` means no qualifying native acceptance artifact was found, not that a
scenario failed. In-flight library, clipboard and other agent source is recorded
as implemented-unverified where present; it is not covered by the column build.
No new live execution or foreground automation was performed for this ledger.

   Remaining object-service extraction retains process-global pools and a
