Implementation

1

Expose the smallest safe backend API

Build on Plan 025. Export a narrow host-facing surface for startup, connections, Query Session operations, event types and shutdown. Keep storage pools, drivers and manager internals private. Connection hydration, safety enforcement and auditing must remain inside the services.

A native crate can depend on the existing backend with default-features = false. Completing every service extraction or moving everything into crates/dbunk-core is not a prerequisite for this slice.

2

Create the native host and connect it to PostgreSQL

Add a separately runnable native application using the spike’s pinned GPUI/Zed dependencies. Own a multi-thread Tokio runtime, start the core monitors, register the window/session owner, and open a fixture connection through the connection service.

Provide a reproducible setup command for an isolated profile with plain SQLite fixture credentials. Use the disposable PostgreSQL service on 127.0.0.1:15432. Never fall back to the daily-driver profile or keychain.

3

Replace synthetic batches with the real event stream

Bridge the core’s typed events into GPUI using a bounded queue. For this first version, preserve the existing sequence, ACK and credit protocol. Acknowledge after consuming the event into the bounded result model. Keep database work off the UI thread.

Fence updates by owner, session, generation and execution. Queue saturation or delivery failure must fail explicitly and release the session, with no silent drops or unlimited buffering. Closing the window must cancel work and await backend cleanup.

4

Finish the query workflow

Show the connection state, SQL editor, Run and Stop controls, results and a clear terminal status. Support multiple result sets, zero-row metadata, command results, notices, database errors and truncation information. Preserve NULLs and exact values in display/copy.

Use the existing SQL statement-boundary logic rather than splitting on every semicolon. Verify execution at the end of a statement, including a trailing semicolon, strings, comments and dollar quotes. After a connection failure, allow an explicit reconnect and a new run.

Keep result cells read-only in this slice. The spike’s staged-edit probe is not a mutation workflow. If retained in the development build, correct its copy and accessibility values so both reflect the displayed staged value.

5

Verify and deliver a reproducible launch

Add a documented just dev-native command or equivalent, with the required toolchain and fixture setup. Exercise the real GPUI-to-core-to-PostgreSQL path, not only the existing backend tests. Record commands, results and remaining limitations.

Run pnpm format, pnpm lint, pnpm typecheck, pnpm test, just fmt, just lint and just test. Include the new native crate in formatting, lint and focused test commands. Keep both backend feature configurations passing.

Done when these pass

Launch and connectA documented command opens the native app on an isolated fixture profile and visibly connects to PostgreSQL.

Real resultsRun a simple query, a multi-statement script, a zero-row result and the wide/large fixtures. Results, metadata and retention limits match the core.

Errors and recoveryInvalid SQL shows the backend error. Lost connections are visible. Explicit reconnect allows another query without old results arriving late.

Stop under loadCancel SELECT pg_sleep(30) and a streaming query, including a slow or full consumer queue. Each execution settles once.

Safe teardownReplace an owner or close the window mid-stream. Tasks and fixture database sessions are released, with no updates to the retired view.

Safety preservedRead-only and Safe Mode refusals still happen before dispatch. The native host cannot bypass the service policy through the public API.
