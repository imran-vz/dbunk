Choose the tool arrangement

DirectionStrengthTradeoff
A · Tool tabsFull width, named state and direct navigation for dense toolsSwitch tabs to compare a tool with its source query
B · Side inspectorSource and details remain visible togetherLong plans and forms need more vertical scrolling
C · Bottom toolsWide tools stay next to the current documentTools share vertical space with SQL and results

Writes remain explicit

EXPLAIN ANALYZE uses the query session and existing policy. Termination, maintenance and reset review identify their exact target.

Failures preserve work

A failed query, stale plan, interrupted job or changed host key shows an actionable state. No SQL or job is replayed automatically.

Connection context stays visible

Each tool names its connection. Saved work opens as a draft. Refresh, diagnosis and execution are deliberate actions.

These are static design examples. They do not demonstrate implemented tools, successful queries or parity acceptance. Result export uses the native file dialog; schema maps retain a full-width document in each direction.
