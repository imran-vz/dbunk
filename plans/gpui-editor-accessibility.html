Make the SQL editor readable to assistive technology

Gate work for the first working GPUI version. Scope: the isolated native spike and its accessibility evidence. Keep the pinned Zed revision and existing layout.

Implementation sequence

  1. Capture the failure. Read the running spike through macOS Accessibility. Assert editor text, focus and selection, rather than only the presence of a text-area role.
  2. Connect the real editor model. Use GPUI’s public synthetic-child hook to publish AccessKit text runs and the primary selection. Route accessibility selection actions back into Zed’s editor. Update on editor changes; avoid building text data when accessibility is inactive.
  3. Verify both directions. Check Unicode offsets, empty text, multiple lines, keyboard editing, undo, caret movement and selection requests through macOS Accessibility.
  4. Record the remaining gate. Run focused tests and required repository checks. Preserve the distinction between automated structural evidence and a human VoiceOver listening check.
